# Habit Quest — Plan 2: Character, Gear and Layered Art

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:**
- Your hero gets **stats** (spending SP), **gear** that drops from quests, can be equipped and changes how the hero looks, and a **class title**.
- The hero is drawn by a **layered sprite system**, so the creator can swap in their own art by replacing PNG files.

**Architecture:**
- **Pure rules in `src/game/`:** stats, gear, drops, class.
- **Content in `src/content/`:** gear catalog, class titles.
- **Art:** PNG sprite strips under `assets/art/`, listed in one manifest (`src/art/manifest.ts`).
- **Rendering:** a `HeroSprite` component stacks layers in a fixed order and steps through frames.
- **Placeholder PNGs** are generated by a script (`scripts/gen-placeholders.mjs`, Playwright rendering SVG) in exactly the format real art uses.
- **Save data** moves to version 2 via a migration.

**Spec:** `docs/superpowers/specs/2026-11-27-habit-quest-design.md` §7, §12.2. **Style:** `docs/design/style-guide.md` (§9 rules apply to every screen).

## Global Constraints
- **Stats are light.**
  - A point is worth a few percent at most.
  - Spending SP at random must still be fine.
  - Respec is free.
- **Weapon type is cosmetic.** Weapons of equal rarity are equally strong.
- **Class title** is weapon type + highest stat. Ties keep the current title. With no weapon equipped, the title is "Wanderer".
- **Saves:** existing v1 saves migrate to v2 with no loss.
- **Art changes need no code changes.** Swapping in real art means replacing a PNG and, if the frame count changes, one manifest number.
- **Art rule:** every layer of one animation shares the same frame size (256×320) and anchor (feet at x=128, y=300).

## Decisions made for the builder (creator can tune all of these in config)

**Stat effects:**
| Stat | Effect per point |
|---|---|
| Power | +3 power rating |
| Speed | −1.5% quest duration, max −20%, applied after the 5 h floor |
| Luck | +1 percentage point drop chance; shifts rarity odds slightly |
| Defense | stored now; boss odds use it in the bosses plan |

**Base power:** `100 + 15 × (level − 1)`. Total power = base + 3×Power + the Power bonuses on equipped gear.

**Gear slots and rarity:**
- Slots: `weapon`, `head`, `body`, `feet`, `accessory`.
- Rarities: common, uncommon, rare, epic, legendary.
- Stat points per item by rarity: 1, 2, 4, 6, 9, spread by the catalog entry.

**Drops (successful quests only):**
- Drop chance: easy 15%, normal 25%, hard 45%, plus Luck.
- Rarity weights: 60 / 28 / 9 / 2.5 / 0.5. Each Luck point moves 0.5 from common to rare.

**Starting gear:** Wooden Sword (common weapon) and Traveller's Tunic (common body), both equipped.

## Review Focus
1. **Migrating a v1 save mid-quest:** the active run, habits and gold survive, and the new fields get defaults.
2. **Equipping gear while questing:** allowed and cosmetic only. It changes neither the stored success chance nor the end time.
3. **Respec:** gives back exactly the SP spent, never more.
4. **A gear id missing from the catalog** (content removed later): no crash. The item is skipped in totals and shown as "Unknown item".
5. **Reduce Motion:** the sprite stays on frame 0 with no bob.

type StatKey = 'power'|'defense'|'luck'|'speed';
type Stats = Record<StatKey, number>;

### Task 5: Art pipeline (manifest, renderer, placeholders, art spec)
**Files:**
- `src/art/manifest.ts`
- `src/art/layers.ts`
- `src/ui/hero/HeroSprite.tsx`
- `scripts/gen-placeholders.mjs`
- `assets/art/**.png`
- `docs/art/art-spec.md`
- Test: `__tests__/art/layers.test.ts`

**Produces:**
```ts
type Anim = 'idle'|'fight';
interface ArtAsset { src: number /* require() */; frames: number; fps: number }
ART: Record<string /* art id */, Partial<Record<Anim, ArtAsset>>>
LAYER_ORDER: LayerName[]   // back → front: accessoryBack, legs, feet, bodyBase, body, arms, head, face, hair, headGear, weapon, glow
heroLayers(p: Player, anim: Anim): { layer: LayerName; asset: ArtAsset }[]   // base layers + equipped gear art, falls back to idle when a layer lacks the anim
HeroSprite({ player, anim, size })   // stacks strips, steps frames at fps, idle bob via transform, Reduce Motion → frame 0
```
- **Base art ids:** `base.body`, `base.head`, `base.face`, `base.hair`, `base.legs`.
- **Gear art:**
  - Each gear item has one art id, drawn on its slot's layer.
  - The weapon has a 4-frame `fight` swing.
  - Rare and better items also get a `glow` layer.
- **The script** draws every layer as SVG at 256×320 per frame, lays the frames out side by side, and screenshots them with Playwright (transparent) into `assets/art/<id>/<anim>.png`.
- **Art spec doc:** canvas, anchor, layer order, naming, frame counts, how to replace a file, and how to preview it.

**Tests:**
- Layer order is stable.
- Equipped gear appears on the right layer.
- Unknown art is skipped.
- A missing `fight` animation falls back to `idle`.
